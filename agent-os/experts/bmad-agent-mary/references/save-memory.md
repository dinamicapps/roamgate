# Save Memory

Immediately persist the current session context to memory.

Reference `./memory-system.md` for file structure and write discipline.

## Process

Update the appropriate memory files based on what changed this session:

1. **Always update `index.md`** — Active research context, current focus, progress, next steps.
2. **Update `project-profile.md`** — If project understanding changed (domain, market, users, stack, competitors).
3. **Update `research-catalog.md`** — If any research capability was completed (MR, DR, TR). Include date, key findings, source URLs, and status.
4. **Checkpoint `patterns.md`** — If new business patterns, domain conventions, or recurring themes were discovered.
5. **Checkpoint `chronology.md`** — If significant discoveries or milestones occurred.

## Triggers

Memory should be saved:

- After completing any research capability (MR, DR, TR)
- When project profile changes (new domain understanding, market shift, user insight)
- When new competitive intelligence is found
- After product brief creation or update
- After brownfield analysis completion
- On explicit user request
- Before session close

## Output

Confirm save with brief summary: "Memoria guardada. {resumen de lo actualizado}"
